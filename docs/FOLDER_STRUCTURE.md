## Key Organizational Principles

### 1. Monorepo Structure (npm workspaces)
```json
// root package.json
{
  "workspaces": [
    "apps/admin",
    "apps/mobile",
    "backend"
  ]
}
```

**Why monorepo**:
- Shared types across frontend/backend
- Easier refactoring (move code between apps)
- Single CI/CD pipeline
- Shared dependencies

### 2. Service Layer Separation
```
Backend structure enforces clear separation:
└─ Routes (HTTP handlers)
   └─ Services (business logic)
      └─ Models (database access)
         └─ Database (raw SQL/ORM)
```

This enables easy extraction of services to microservices later.

### 3. Testing Pyramid
```
┌─────────────────────────────────────┐
│   E2E Tests (full flows)            │ 5%
├─────────────────────────────────────┤
│  Integration Tests (service chains) │ 25%
├─────────────────────────────────────┤
│  Unit Tests (function-level)        │ 70%
└─────────────────────────────────────┘
```

### 4. Configuration Management
```
.env (git-ignored)
├─ Development (localhost, mock payment provider)
├─ Staging (AWS, real Paystack sandbox)
└─ Production (AWS multi-region, real providers)

Config hierarchy:
code defaults → environment variables → secrets manager (AWS)
```

### 5. Database Migration Strategy
```
Pending MVP → Multi-Region transformation:

Phase 1: Prepare (run alongside MVP)
├─ Create new tables (countries, currencies, etc.)
├─ Create new wallet/ledger system
└─ Implement dual-write layer

Phase 2: Dual-Write (1-2 weeks validation)
├─ Write to both old and new systems
├─ Compare balances, verify consistency
├─ Run shadow read test (read from new, validate against old)

Phase 3: Cutover (30-minute window)
├─ Stop writes to old system
├─ Final reconciliation
├─ Switch reads to new system

Phase 4: Cleanup (after 30 days stability)
├─ Archive old tables
├─ Remove dual-write layer
└─ Deprecate legacy code
```

## Scaling Checklist

As platform grows, move from monolith to services:

```
Phase 1 (Current - 100k users):
└─ Monolith with strong service layer separation

Phase 2 (1M users):
├─ Extract: Auth Service
├─ Extract: Payment Service (highest throughput)
├─ Extract: Notification Service
└─ Keep: Wallet, Group, Admin (can share DB)

Phase 3 (5M users):
├─ Extract: Ledger Service (event sourcing)
├─ Extract: Fraud Detection Service (ML)
├─ Extract: Settlement Service (batch processing)
└─ Migrate to: Event-driven architecture (Kafka)

Phase 4 (10M+ users):
├─ Per-region microservice clusters
├─ Dedicated DBs per service (data federation)
├─ Service mesh (Istio) for inter-service communication
└─ Full CQRS + Event Sourcing for ledger
```
